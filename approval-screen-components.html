Approval queue, components

Every part of the screen, on its own, with its states. Each block has an id, so a change can be asked for as “C4 hover is too strong” or “change the C2 count chip” and only that part moves in approval-screen-design-v2.html.

Every value on this sheet is read from workflow_platform.db or derived from it, and each derivation says what it is derived from. Nothing here is illustrative.

text faint is for disabled controls and nothing else. It measures 2.57:1 on white and WCAG 2.1 AA wants 4.5:1 for body text. Darkening it until it passes lands exactly on text muted, so it is not a missing colour, it is a colour with one narrow job. Every use of it on the approval screen carried information, counts, timestamps, a breadcrumb, a role, a placeholder and the sentence naming the Jira task, so all eighteen moved to text muted and it now appears nowhere on the delivered screen. text disabled measures 1.57:1 and stays, because WCAG 2.1 1.4.3 exempts inactive controls by name.

Three chromatic colours only: accent for what a person can do, caution for doubt, positive for settled. Positive appears at 7px and never larger, because nobody needs their eye pulled to a document that is already fine.

What the rail encodes, and why neither the screen nor the card above draws one. The rail is the document's age against the oldest document waiting, so the queue sorted “Oldest first” reads as a descending stair. It is age rather than money because money on this screen arrives in more than one currency, and a bar that compares USD to AUD would be exactly the arithmetic this pipeline is being watched for. With one document waiting the rail is always full, which is indistinguishable from a rule and says nothing, so it is drawn above as the rule it is and left off both the card and approval-screen-design-v2.html. It earns its place from two documents up, and the 4d row above is the shape it would take, not a document that exists. At three hundred the card compresses to the two-line variant above and the rail stays.

Six signals exist and the first match wins, so a card never carries two warnings competing for the same glance. The three not drawn here are the gate failing, the total being recovered by our own code rather than read, and the vendor name being inferred. Copy changes belong in review_signals.py; if this sheet and that file disagree, the file is right.
